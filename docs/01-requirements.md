## 1. 개요

### 1.1 목적
PC를 켜고 로그인한 뒤 "언제부터 PC를 써도 되는지"를 실시간으로 보여준다. 바탕화면이 떴어도 시작프로그램과 백그라운드 작업 때문에 한동안 버벅이는 구간이 있는데, 이 구간이 끝나는 시점을 판정해 알려주고, 무엇이 그 시점을 늦췄는지 평가·추천한다.

### 1.2 기존 도구와의 차이
| 도구 | 하는 일 | 땡해줘와의 차이 |
|---|---|---|
| BootRacer | 부팅·로그온 시간 측정 | 숫자만 제공. 땡해줘는 진행 중 상태와 남은 항목을 실시간 표시 |
| Autorun Organizer, Autoruns | 시작 항목 관리 | 로그인 후 바쁜 원인을 보여주지 않음 |
| 이벤트 뷰어 Event 100 | 부팅 시간 기록 | 사후 기록, XML 확인 필요, 관리자 권한 필요 |
| WPR/WPA | 정밀 트레이스 분석 | 전문가용, 수동 캡처 |
| uberAgent 등 | 기업용 지표 수집 | 유료, 개인 사용 불가 |

### 1.3 범위
- **포함**: 로그온 후 실시간 진행 오버레이, 체크리스트 판정, 시작 항목별 안정화 추적, 네트워크 연결 확인, 백그라운드 작업 표시, 부팅 이력 저장·비교, 평가 등급, 근거 기반 추천, 자동 시작 등록, 트레이 아이콘, 데모 측정
- **제외**: 시작 항목 자동 비활성화(안내만 함), 로그인 전 구간의 실시간 표시, 잠자기 해제(wake) 측정, 다국어(한국어만), 서버·계정·원격 전송

### 1.4 운영 조건
- 플랫폼: Windows 10/11, macOS 13 이상
- 권한: 일반 사용자 권한으로 동작. 관리자 권한이 있으면 추가 정보(Event 100)를 읽음
- 네트워크: 연결 확인용 접속(Windows `www.msftconnecttest.com:80`, Mac `captive.apple.com:80`)만 사용. 수집 데이터는 외부로 보내지 않음

## 2. 용어

| 용어 | 정의 |
|---|---|
| 기준 시각 (t=0) | 바탕화면이 표시된 시각. Windows는 `explorer.exe`, Mac은 `Dock` 프로세스의 시작 시각 |
| 시작 항목 | 로그인 시 자동 실행되도록 등록된 프로그램. 등록 목록에서 읽은 항목과 자동 감지 항목이 있음 |
| 자동 감지 항목 | 등록 목록에 없지만 기준 시각 직후 사용자 세션에서 시작된 비시스템 프로그램 |
| 프로세스 트리 | 시작 항목 프로세스와 그 자식(손자 포함) 프로세스 전체 |
| 안정 | 시작 항목의 프로세스 트리가 조용해진 상태 (§4.2) |
| 사용 가능 | 필수 체크리스트가 모두 충족된 상태 (§4.1) |
| 백그라운드 작업 | 판정을 막지 않고 참고로 표시하는 작업 (Defender, Spotlight, 지속형 항목 등) |
| 지속형 | 실행 후 60초 안에 안정되지 않아 판정에서 빠진 항목 |

## 4. 판정 규칙

### 4.1 필수 체크리스트
아래 세 조건이 모두 충족된 상태가 **3초** 유지되면 "사용 가능"으로 판정한다.

| # | 조건 | 충족 기준 |
|---|---|---|
| C1 | 바탕화면 표시 | 기준 시각 확보 |
| C2 | 시작 항목 | 모든 항목이 안정·미실행·지속형·추적 불가 중 하나 |
| C3 | 네트워크 | 연결 확인 성공, 또는 30초 경과(네트워크 없음) |

사용 가능 시각은 세 조건이 마지막으로 모두 충족되기 시작한 시각으로 기록한다.

### 4.2 항목별 안정 판정
| 항목 | 값 |
|---|---|
| 조회 간격 | 1초 |
| 측정 단위 | 프로세스 트리 합계 |
| 판정 창 | 최근 5초 |
| CPU | 5초 평균이 코어 1개 기준 **8% 미만** (v1.1 변경, §9) |
| 디스크 | 5초 평균 읽기+쓰기 1 MB/s 미만 |
| 자식 프로세스 | 5초 안에 새 자식 프로세스 생성 없음 |
| 최소 관찰 | 처음 관찰 후 3초 이전에는 판정하지 않음 |
| 안정 시점 | 조건을 처음 만족한 5초 창의 시작 |
| 트리 전체 종료 | 런처가 실행 후 종료된 경우 → 안정으로 처리 |
| 재활성 | 안정 판정 후 CPU 20% 이상 3초 지속 시 진행 중으로 되돌림. 사용 가능 선언 전까지만 적용 |

### 4.3 타임아웃과 예외
| 상황 | 값 | 처리 |
|---|---|---|
| 등록됐으나 실행되지 않음 | t=45초 | 미실행 → 판정 제외 |
| 직전 부팅에서 미실행이었던 항목 | — | 기다리지 않음. 실행되면 그때부터 일반 항목처럼 추적 (v1.1 추가) |
| 실행됐으나 안정되지 않음 | 실행 후 60초 | 지속형 → 백그라운드로 이동 |
| 실행 파일을 특정할 수 없는 항목 (.bat, .vbs 등) | — | 추적 불가 → 판정 제외 |
| 네트워크 미연결 | t=30초 | 네트워크 없음 → 판정을 막지 않음 |
| 전체 상한 | t=5분 | 사용 가능(일부 지연)으로 강제 판정 |

### 4.4 보조 지표
시스템 CPU 사용률 20% 이하(유휴 80% 이상) 구간이 누적 10초가 된 시각을 "시스템 안정(보조)"으로 기록한다. Microsoft의 Post Boot 정의를 1초 단위로 근사한 값이며, 디스크 유휴율은 운영체제 공통 API가 없어 제외한다. 판정에는 쓰지 않는다.

## 5. 기능 요구사항

### F1. 자동 시작
- F1-1 첫 실행 시 로그인 자동 시작을 등록한다.
- F1-2 Windows는 작업 스케줄러 "로그온 시" 작업 등록을 먼저 시도하고, 실패하면 `HKCU\...\Run`으로 등록한다. 사용한 방식을 상세 화면에 표시한다.
- F1-3 Mac은 `~/Library/LaunchAgents`에 `RunAtLoad` LaunchAgent를 등록한다.
- F1-4 트레이 메뉴에서 켜고 끌 수 있다.

### F2. 측정 세션
- F2-1 실행 시 기준 시각이 10분 이내면 부팅 측정 세션을 시작한다. 10분이 넘었으면 측정하지 않고 상세 화면(이력)을 연다.
- F2-2 1초마다 프로세스 목록을 조회해 항목 상태를 갱신하고 화면에 보낸다.
- F2-3 사용 가능 판정 후 20초 더 관찰해 백그라운드 작업을 기록한 뒤 세션을 종료하고 조회를 멈춘다.
- F2-4 세션 종료 후 로그온 예약 작업 목록을 갱신해 캐시한다(조회 비용이 커서 부팅 중에는 하지 않음).

### F3. 시작 항목 수집
- F3-1 Windows: `HKCU`/`HKLM`/`WOW6432Node`의 `Run` 키, 사용자·공용 시작 폴더(.lnk 대상 경로 해석), 로그온 예약 작업 캐시. `StartupApproved`에서 비활성 표시된 항목은 제외한다.
- F3-2 Windows 로그온 예약 작업 중 `\Microsoft\Windows\` 경로와 Windows 폴더 안의 실행 파일은 시스템 작업으로 보고 제외한다.
- F3-3 Mac: `~/Library/LaunchAgents`, `/Library/LaunchAgents`의 plist 중 `RunAtLoad=true`이고 `Disabled`가 아닌 항목.
- F3-4 두 OS 공통: 자동 감지 항목(§2)을 추가한다. Mac의 로그인 항목·윈도우 복원 앱은 이 방식으로 잡는다.

### F4. 실시간 오버레이
- F4-1 주 모니터 작업 영역의 오른쪽 아래에 작은 창으로 표시한다. 항상 위, 작업표시줄 미표시, 포커스를 가져가지 않는다.
- F4-2 상단: 상태 문구, 경과 시간, 진행률(안정 항목 수 / 전체 항목 수). 상태 문구는 사용 가능 판정 전에는 **"얼음!"**(하늘색), 판정 후에는 **"땡!"**(초록)으로 크게 표시한다. 타임아웃으로 빠진 항목이 있으면 "땡!" 옆에 "일부 지연"을 붙인다. (v1.2)
- F4-3 체크리스트 C1~C3의 상태.
- F4-4 항목 목록: 이름, 상태, 현재 CPU, 경과 시간. 아직 안정되지 않은 항목이 위로 온다.
- F4-5 백그라운드 작업 목록.
- F4-6 사용 가능 판정 즉시 등급을 보여준다. 20초 추가 관찰(F2-3)이 끝나면 추천 1건을 보여주고 15초 뒤 자동으로 숨긴다. 마우스를 올리면 숨기지 않는다.
- F4-7 "자세히" 버튼으로 상세 화면을 연다.

### F5. 상세 화면
- F5-1 마지막 부팅의 타임라인: 항목별 실행~안정 막대와 사용 가능 시점 표시선.
- F5-2 평가 등급과 추천 전체.
- F5-3 부팅 이력 표(최근 30회): 일시, 부팅 종류, 사용 가능 시간, 등급, 병목 항목.
- F5-4 자동 시작 방식과 설정.

### F6. 평가
| 등급 | 사용 가능까지 (t=0 기준) |
|---|---|
| A | 30초 이하 |
| B | 60초 이하 |
| C | 120초 이하 |
| D | 120초 초과 또는 강제 판정 |

### F7. 추천 (측정 근거가 있는 것만)
| 규칙 | 조건 | 내용 |
|---|---|---|
| R1 병목 | 가장 늦게 안정된 항목이 t=15초 이후 안정 | 이 항목이 사용 가능 시점을 정함. 시작 시 실행 해제 또는 지연 검토 |
| R2 지속형 반복 | 최근 3회 중 2회 이상 지속형 | 업데이트·동기화가 매번 도는지 확인 |
| R3 미실행 반복 | 최근 3회 모두 미실행 | 등록만 남은 항목일 수 있음 |
| R4 느려짐 | 이전 5회 중앙값 대비 20% 이상이면서 5초 이상 늦음 | 이번에 새로 나타난 항목 표시 |
| R5 네트워크 지연 | 네트워크 연결이 t=20초 이후 | Wi-Fi 자동 연결·드라이버 확인 |

- 추천에는 해제 방법(Windows: 설정 > 앱 > 시작 프로그램, Mac: 시스템 설정 > 일반 > 로그인 항목)을 함께 적는다.
- 프로그램이 시작 항목을 직접 끄거나 바꾸지 않는다.

### F8. 부팅 종류
- Windows: 기준 시각 − 부팅 시각이 10분 초과면 "빠른 시작(추정)", 아니면 "콜드 부팅".
- Mac: "콜드 부팅".
- 데모 측정은 이력에 저장하지 않는다.

### F9. 트레이
메뉴: 열기(상세), 지금 측정해 보기(데모), 로그인 시 자동 실행(체크), 종료.
툴팁: 측정 중 "땡해줘 · 얼음!", 판정 후 "땡해줘 · 땡!". (v1.2)

### F10. 데모 측정
현재 시각을 기준 시각으로 놓고 같은 판정을 실행한다. 부팅 직후가 아니어도 화면과 판정 동작을 확인할 수 있다.

### F11. 업데이트 (v1.3)
- F11-1 배포: 태그 `vX.Y.Z` push → GitHub Actions가 Windows(NSIS)·macOS(universal)를 빌드·서명하고 `lsft32/ttaeng` 릴리스에 설치 파일과 `latest.json`을 올린다. 두 빌드가 모두 성공한 뒤에 게시한다.
- F11-2 확인 시점: **측정 중에는 확인하지 않는다.** 측정이 끝난 뒤(또는 측정 없이 시작된 경우 시작 직후), 상세 화면을 볼 때 자동 확인하되 6시간에 한 번까지. 트레이·상세 화면의 "업데이트 확인"은 간격 제한 없음.
- F11-3 설치: 자동 설치하지 않는다. 새 버전이 있으면 상세 화면 배너와 트레이 항목("업데이트 설치 (버전)")으로 알리고, 사용자가 누르면 내려받아 설치(Windows는 진행 창만 보이는 passive)한 뒤 다시 실행한다. 측정 중에는 설치 버튼을 막는다.
- F11-4 업데이트 설치는 자동 시작 등록·설정·이력을 유지한다(NSIS `/UPDATE` 모드에서 제거 훅이 동작하지 않음).
- F11-5 서명: 업데이트 파일은 땡해줘 전용 키로 서명하고, 앱은 내장 공개키로 검증한다. 개인키는 개발 PC `~/.tauri/ttaeng.key`와 GitHub Secrets에만 둔다.

## 6. 비기능 요구사항

## 7. 알려진 제약
| 제약 | 영향 | 대응 |
|---|---|---|
| Event 100은 관리자 권한 필요 | 로그인 전 단계 시간은 일반 권한에서 표시 불가 | 읽을 수 있으면 표시, 아니면 "부팅~바탕화면(로그인 대기 포함)"만 표시 |
| Windows 프로세스 I/O 수치는 디스크 외 I/O 포함 | 디스크 기준이 다소 보수적 | 문서에 명시 |
| 관리자/시스템 프로세스(Defender 등)는 일반 권한으로 CPU를 못 읽을 수 있음 | 백그라운드 표시 누락 가능 | 읽히는 것만 표시 |
| Mac 로그인 항목 목록을 일반 권한으로 읽는 공식 API 미확인 | 등록 목록에 안 잡힘 | 자동 감지로 대체 |
| Mac BTM에서 "백그라운드 허용"이 꺼진 LaunchAgent | 미실행으로 표시됨 | 미실행은 판정에서 제외되므로 결과에는 영향 없음 |
| 프로그램 자신보다 먼저 시작된 항목 | 자식 연결 일부 누락 가능 | 프로세스 시작 시각으로 소급, 자동 감지로 보완 |
| Mac 빌드·실행 미검증 | 개발 PC가 Windows | Mac 실기 확인 필요 (§8) |
| 판정 수치는 근거 기반 기본값 | 실측 검증 전 | 실사용 로그로 1회 조정 예정 |
