# Phase 11 — 체감 반응 지표 (v0.3.5)

| 항목 | 내용 |
|---|---|
| 일자 | 2026-11-05 |
| 근거 | 사용자 질문 "땡!을 기다렸다 쓰는 게 실제 사용성에 영향이 있나" → 안 B(체감 지표 추가) 선택 |
| 요구서 | v1.7 (F12, R8, §9) |

## 배경
- 땡해줘는 "시작프로그램이 조용해졌는가"만 재고, "PC 반응이 실제로 느렸는가"는 재지 않았다
- 개발 PC(Core Ultra 5 125H 18스레드, NVMe, 32GB) 11/05 10:23 기록: 땡!(104초)까지 시작프로그램 부하가 CPU 182코어·초(평균 약 1.75코어, 전체의 약 10%), 디스크 347MB(초당 약 3MB)
- 이 수준이면 땡! 전에도 체감 차이가 작을 수 있으나 근거가 없음 → 측정으로 확인

## 설계
| 항목 | 내용 |
|---|---|
| 지표 | 타이머(1ms 대기 5회의 초과 평균), 계산(FNV 20만 회), 디스크(4KB 쓰기 + flush) |
| 주기 | 측정 내내 2초 |
| 기준값 | 측정 직후 10회(약 5초) 중앙값. 설정에도 저장해 다음 측정의 오버레이 표시에 사용 |
| 느려진 정도 | **타이머·디스크** 배율 중 최댓값(계산은 기록만), 연속 5표본(10초) 중앙값. 최소 기준 타이머 1ms·계산 0.5ms·디스크 2ms |
| 반응 회복 | 1.5배 이하가 10초 이어지기 시작한 시각 |
| 비교 | 추천 R8: 회복이 땡!보다 20초 이상 빠름/늦음, 끝까지 미회복 |
| 판정 반영 | 아직 안 함(비교만). 실측이 쌓이면 땡! 기준 보정을 검토 |

## 화면
- 상세: "반응 회복" 카드(땡!과 차이), "체감 반응" 그래프(느려진 정도, 땡! 선, 반응 회복 선, 점마다 세 지표 툴팁)
- 오버레이: 1.5배 이상이면 "반응 평소의 N배"(직전 측정 기준값 대비)

## 함께 고친 것
- 업데이트 알림이 스크롤된 상세 화면에서 안 보이던 문제(11/03 0.3.4 업데이트 때): 고정 헤더의 버튼이 새 버전이 있으면 "x.y.z 설치"로 바뀌고, 직접 확인했는데 새 버전이 없으면 "최신 버전입니다"를 4초 표시

## 주의
- 디스크 측정 실패는 -1로 기록(NaN은 JSON에 null로 저장돼 다시 읽을 때 오류). 배율 계산에서 제외
- 하이브리드 CPU(P/E 코어)에서는 계산 지표가 어느 코어에서 도느냐에 따라 흔들릴 수 있어 중앙값으로 누름

## 유휴 잡음 실측과 조정
| 지표 | 중앙 | 90% | 최대 |
|---|---|---|---|
| 타이머 | 0.54ms | 0.82ms | 1.79ms |
| 디스크 | 5.7ms | 7.8ms | 8.4ms |
| 계산(릴리스) | 0.53~0.74ms | — | — |

- 처음 안(최소 기준 타이머 0.5ms·디스크 1ms, 3표본 중앙값)은 유휴에서도 1.5배를 넘는 표본이 생김(타이머 90% 값이 1.64배)
- 최소 기준을 타이머 1ms·디스크 2ms로 올리고 5표본 중앙값으로 바꿈

## 데모로 확인한 것과 조정 (디버그 빌드, 유휴 상태)
| 회차 | 결과 | 해석 |
|---|---|---|
| 1 | 반응 회복 "측정 중 미회복", 최대 2.6배 | 부팅 부하가 없는데 느려짐으로 나옴 → 지표 쪽 문제 |
| 2 | 1.0~1.3배, 회복 0.1초, R8 "땡!보다 60초 일찍 써도 차이 작음" | 정상 |
| 3 (계산 지표 제외·기준값 10회 적용 후) | 시작 2~4초 22.4배 튐 → 이후 약 1.2배, 회복 6.6초, R8 정상 | 앱 시작과 릴리스 빌드(cargo)를 동시에 시작한 시점이라 실제 부하로 봄. 큰 튐 때 축 눈금 겹침 → 수정 |

- 앱 자신의 1초 프로세스 조회가 지표를 부풀리는지 실험(조회 없음/있음 각 10회): 중앙값 차이 없음(타이머 0.66/0.64ms, 디스크 5.15/5.51ms) → 원인 아님
- 유휴에도 가끔 큰 튐 있음(타이머 최대 9.2ms, 계산 10.8ms, 디스크 18.8ms) → 중앙값 처리 필요성 확인
- 회차 1의 원인 추정: 하이브리드 CPU에서 계산 지표가 코어 배치(P/E)에 따라 흔들림. 확정은 못 했으나, 같은 조건에서 결과가 갈렸으므로 계산 지표를 판단에서 빼고 기준값 표본을 10회로 늘림
